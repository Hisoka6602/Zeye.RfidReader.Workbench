# 架构说明

## 当前分层定位

- `Contracts`：统一放置跨层共享的接口、枚举、事件载荷、设备配置模型与通用契约。
- `Application`：仅保留应用编排入口与 `Options` 配置模型，不承担设备通信实现。
- `Infrastructure`：负责驱动注册、会话创建与基础设施实现。
- `Avalonia`：负责桌面端界面、CommunityToolkit.Mvvm 视图模型、依赖注入组合根工厂与动画封装，不直接编排设备通信。
- `Domain`：暂保留领域标签对象等纯领域元素。

## 本次结构对齐

### Contracts 统一承载共享契约

本次已将以下类型迁移到 `src/Zeye.RfidReader.Workbench.Contracts`：

- `Enums/Devices`：`RfidReaderVendorType`、`RfidReaderProtocolType`、`RfidReaderConnectionState`、`RfidReaderCapability`。
- `Abstractions/Devices`：`IRfidReaderSession`。
- `Abstractions/Drivers`：`IRfidReaderDriverFactory`。
- `Abstractions/Time`：`ILocalClock`。
- `Events/Devices`：`RfidTagReadEventArgs`、`RfidReaderStatusChangedEventArgs`、`RfidReaderFaultedEventArgs`、`RfidReaderEventHandler`。

其中三个事件载荷均改为 `readonly record struct`，继续保持本地时间字段命名与语义。

### Avalonia 启动结构与 MVVM 基线

- `Program.cs` 仅负责启动 Avalonia。
- `App.axaml.cs` 仅负责调用 `AvaloniaServiceProviderFactory` 创建和释放 `ServiceProvider`，避免在 `Program.cs` 暴露全局静态容器。
- `ViewModelBase` 基于 `CommunityToolkit.Mvvm.ObservableObject`，统一提供属性变更通知能力。
- `MainWindowViewModel` 已改为真正的 MVVM 视图模型，负责界面展示文案与启动/停止命令，不引入 RFID 设备通信逻辑。
- `MainWindow` 已删除无参构造函数，只允许通过 DI 注入 `MainWindowViewModel`。

## Lottie 动画接入

桌面工程已固定使用以下版本组合：

- `Avalonia.Desktop`：`12.0.2`
- `Avalonia.Themes.Fluent`：`12.0.2`
- `CommunityToolkit.Mvvm`：`8.4.2`
- `Avalonia.Labs.Lottie`：`12.0.2`

当前主窗口通过 `Controls/RfidLottieView` 封装本地 `AvaloniaResource` 动画资源，用于占位展示设备连接态动效。当前继续保留 `Avalonia.Labs.Lottie 12.0.2`，原因是该包与现有 Avalonia `12.0.2` 版本组合一致，可在不引入第二套 UI 框架的前提下完成统一控件封装。后续若要绑定真实状态，应由 Application 服务向 UI 投递状态，再由 ViewModel 驱动动画切换。

## CI 门禁概览

CI 工作流执行以下步骤：

1. `dotnet restore`
2. `dotnet build --configuration Release --no-restore`
3. `dotnet test --configuration Release --no-build`
4. 额外执行架构门禁脚本，检查 Avalonia 与 MVVM 版本、禁止手动创建窗口与 ViewModel、禁止 `App.axaml.cs` 直接构建容器、禁止主窗口保留无参构造函数、禁止主窗口直接引用 `lottie:Lottie`、要求存在 `ViewModelBase` / `AvaloniaServiceProviderFactory` / `Avalonia.Tests`、README 与 Copilot 规则文件存在性、Markdown 命名、NLog 配置要求等。

## Avalonia.Tests

新增 `tests/Zeye.RfidReader.Workbench.Avalonia.Tests`，当前用于验证 `MainWindowViewModel` 的启动/停止命令只更新 UI 状态，不越层访问真实设备通信实现。该测试项目与现有 `xUnit` 风格保持一致，并纳入解决方案与 CI 执行范围。

## 设备配置模型调整

为消除 `Contracts -> Application` 反向依赖，本次将共享设备配置模型提前沉淀到 `Contracts/Models/Devices`，包括单设备配置、TCP/串口/SDK 连接配置与读码配置。`Application/Options/RfidReadersOptions` 保留为应用配置根节点，用于组合这些共享模型。
