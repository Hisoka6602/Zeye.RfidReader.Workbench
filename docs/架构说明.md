# 架构说明

## 当前分层定位

- `Contracts`：统一放置跨层共享接口、枚举、事件载荷、设备配置模型与通用契约。
- `Application`：仅保留应用编排入口与 `Options` 配置模型，不承担设备通信实现。
- `Infrastructure`：负责驱动注册、会话创建、模拟实现与基础设施能力。
- `Avalonia`：负责桌面端界面、MVVM 视图模型、Shell、页面、导航/通知/线程服务与动画控件，不直接编排设备通信。
- `Domain`：暂保留领域标签对象等纯领域元素。

## 本次 UI 底座结构对齐

### Avalonia 分层目录

本次已将 `src/Zeye.RfidReader.Workbench.Avalonia` 对齐为以下职责边界：

- `Bootstrap`：仅保留 Avalonia 容器创建入口。
- `Controls`：仅放置可复用 UI 控件。
- `Models`：定义 UI 展示模型。
- `Services`：定义导航、对话框、通知与 UI 线程调度抽象及实现。
- `ViewModels`：仅维护 UI 状态、命令与页面展示数据。
- `Views`：仅放置 Shell 与页面视图，不承载业务逻辑。

### Shell 与页面结构

- `MainWindow` 作为桌面 Shell，负责承载左侧导航、顶部状态栏、内容区与底部 Lottie 区域。
- `MainWindowViewModel` 仅维护页面标题、状态文本、Lottie 路径、启动/停止按钮状态、导航集合与当前页面。
- 页面占位统一拆分为 `Dashboard`、`ReaderMonitor`、`Settings`、`Logs` 四组 View + ViewModel。
- `App.axaml` 通过 DataTemplate 建立 ViewModel 到 View 的映射，不引入额外路由框架。

### UI 服务基线

UI 层底座已包含：

- `IAppNavigationService` / `AppNavigationService`：统一页面切换与当前页面广播。
- `IDialogService` / `DialogService`：统一对话框入口。
- `IToastNotificationService` / `ToastNotificationService`：统一通知提示入口。
- `IUiDispatcher` / `AvaloniaUiDispatcher`：统一 UI 线程投递与异步调度。

这些服务均通过 Avalonia DI 注册，供 Shell 与后续页面扩展复用。

## Lottie 动画控件调整

桌面工程继续固定使用以下版本组合：

- `Avalonia.Desktop`：`12.0.2`
- `Avalonia.Themes.Fluent`：`12.0.2`
- `CommunityToolkit.Mvvm`：`8.4.2`
- `Avalonia.Labs.Lottie`：`12.0.2`

`Controls/RfidLottieView` 已从直接绑定 `MainWindowViewModel` 改为通过 `StyledProperty` 接收动画资源路径。这样可以让控件脱离特定 Shell 复用，后续页面或对话框可直接复用同一动画封装，而不会把 Shell 视图模型耦合到控件内部。

## ViewModel 边界

当前 UI ViewModel 继续遵循以下约束：

- 只负责 UI 状态与命令，不直接引用 `Infrastructure`。
- 不直接创建 `IRfidReaderSession` 或 `SimulatedRfidReaderSession`。
- 不接入真实厂商 SDK、TCP、串口、数据库或外部业务系统。
- 启动/停止命令当前仅更新 `IsRunning` 等 UI 状态，用于基线验证。

## 测试与 CI 门禁

### Avalonia.Tests

`tests/Zeye.RfidReader.Workbench.Avalonia.Tests` 当前覆盖以下基线行为：

- `MainWindowViewModel` 默认导航到 `Dashboard`。
- `NavigateCommand` 可以切换到 `ReaderMonitor`。
- `StartReadingCommand` / `StopReadingCommand` 只更新 UI 运行状态。
- `AppNavigationService` 遇到未知页面键时抛出中文异常。
- `ToastNotificationService` 能触发通知事件并生成本地时间戳。

### CI 门禁概览

CI 工作流执行以下步骤：

1. `dotnet restore`
2. `dotnet build --configuration Release --no-restore`
3. `dotnet test --configuration Release --no-build --no-restore`
4. 架构门禁脚本额外检查以下内容：
   - Avalonia 与 MVVM 版本固定不变，且禁止引入 `ReactiveUI`、`Avalonia.ReactiveUI`、`Prism.Wpf`、`MediatR`、`Splat`。
   - `IAppNavigationService`、`AppNavigationService`、`IDialogService`、`DialogService`、`IToastNotificationService`、`ToastNotificationService`、`IUiDispatcher`、`AvaloniaUiDispatcher`、`DashboardViewModel`、`DashboardView` 等 UI 基线文件必须存在。
   - `MainWindow.axaml` 禁止直接使用 `lottie:Lottie`。
   - `MainWindowViewModel` 禁止引用 `Infrastructure` 命名空间。
   - Avalonia ViewModel 禁止直接创建 `SimulatedRfidReaderSession`。
   - 继续检查 README、Markdown 命名与 NLog 配置等仓库级规则。
