# 厂商接入指南

## 参考 ZakYip.PlcBridge 的借鉴原则

本项目借鉴 `Hisoka6602/ZakYip.PlcBridge` 客户端连接处理经验，但不直接照搬 WPF 与 SignalR 具体实现。当前确认保留的原则如下：

1. 连接状态必须可观察，并通过事件通知上层。
2. 自动重连必须具备并发保护，避免重复启动后台重连任务。
3. 连接失败、断开失败、事件回调失败都必须记录日志，且不能炸穿 UI 主流程。
4. 请求调用失败应返回失败结果或状态，而不是直接让界面线程承受异常。
5. 配置解析优先读取已知字段，缺失配置时抛出中文异常。

## 本项目禁止照搬的做法

以下做法在本项目中明确禁止：

- ViewModel 直接订阅底层设备客户端事件。
- ViewModel 直接持有 RFID 客户端并发起设备连接。
- 使用 WPF `Application.Current.Dispatcher` 风格在 UI 层直接处理设备消息。
- 在热路径反复读取配置文件。
- 在 Avalonia `App.axaml.cs` 中直接 `BuildServiceProvider` 或直接创建 `ServiceCollection`。
- 在 `MainWindow.axaml` 中直接散落动画控件实现，而不复用统一的 `RfidLottieView`。

## 推荐落地方向

### 连接编排

后续真实客户端落地时，应由 Application 服务负责：

- 统一订阅底层设备事件。
- 进行状态转换、异常兜底与重连节流。
- 再将适合 UI 消费的状态投递给 ViewModel。

### 配置加载

- `Application/Options` 继续定义结构。
- `Infrastructure` 或宿主组合根负责在启动阶段绑定配置。
- 所有时间相关配置默认按本地时间解释，不得引入 `Z` 或 offset。

### UI 组合根

- Avalonia 宿主只允许通过 `Bootstrap/AvaloniaServiceProviderFactory` 创建容器。
- `MainWindow` 必须通过依赖注入解析，禁止保留无参构造函数绕过 DI。
- ViewModel 统一继承 `ViewModelBase`，只负责 UI 状态，不承载真实厂商通信。

### 厂商扩展

新增厂商驱动时，只允许在 `Infrastructure/Drivers/Vendors/{VendorName}` 下实现驱动，避免污染 `Contracts` 与 `Application` 的稳定边界。
